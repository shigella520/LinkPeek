# 分享总结整体重新生成方案

状态：已实现。原分享链接保持不变、全部成功后切换、旧版本保留。以下规则已作为本次实现范围。

## 功能定义

针对一条已有分享总结，重新生成文字，再基于新文字生成图片和音频。三项全部成功后，将该总结的公开展示版本一次性切换为新版本。

- 入口统一称为「重新生成分享总结」。
- 重新生成沿用原记录的时间窗口，不按当前时间重新计算周期。
- 生成期间和失败后，公开页面继续展示上一完整版本。
- 原分享页面链接始终可用；旧图片、音频文件地址继续指向原文件。
- 历史版本在后台可查看，不在本期增加手动回滚、版本比较或取消任务。

## 生成范围与输入

1. 使用原记录的 `windowStart`、`windowEnd` 和周期类型。
2. 使用任务当前的提示词、链接数量限制，以及当前可用的文字、图片、音频服务配置。提交时固定本次非敏感配置快照；密钥仍从安全配置读取，不写入版本快照。
3. 在原窗口重新查询链接数据，并保存本次实际输入快照。固定窗口不代表原始链接数据完全不变，历史记录目前也不足以还原当时全部输入。
4. 为使「整体」语义明确，本入口要求文字、图片、音频服务均可用。配置缺失或服务禁用时，在调用模型前拒绝并指出缺少的配置。
5. 图片、音频的 `autoGenerate` 开关仅影响普通任务的自动生成；整体重新生成是显式请求，不受该开关控制。
6. 任务已删除时，本期不接受整体重新生成，并说明原因。任务仅关闭定时执行时，仍允许手动重新生成。
7. 无有效输入或未达到最小链接数时，本次结束为「无可生成内容」，不发布空版本，不替换已有内容。

## 流程与状态

```text
校验配置、锁定本次输入 → 创建待生成版本 → 生成文字及统一标题/摘要
                                               ├→ 生成图片 ─┐
                                               └→ 生成音频 ─┤
                                                            ↓
                                                   全部成功后统一发布
```

标题、摘要与正文属于同一版本。图片和音频均读取该版本的固定输入，音频不能再从其他版本的图片记录中取得标题、摘要。

后台分别展示「当前已发布版本」和「本次重新生成进度」。建议为重新生成增加独立状态：排队中、生成文字中、生成素材中、已完成、部分失败、失败、无可生成内容。图片、音频各有子状态；文字成功不等于整体完成。

| 场景 | 处理 |
| --- | --- |
| 文字失败 | 不启动图片和音频；保留已发布版本。 |
| 图片或音频失败 | 另一项可继续完成；保留本次成功结果，整体不发布。 |
| 重试未完成部分 | 沿用本次成功文字及输入，仅重试失败或未完成的部分；不重复生成已成功内容。 |
| 再次选择整体重新生成 | 创建新的候选版本，从文字重新开始；失败候选版本留在历史中。 |
| 三项全部成功 | 在一个数据库事务内切换公开版本并标记完成。 |
| 原记录没有成功版本 | 后台仍可重试；全部成功前不提供不完整的新公开版本。 |

「重试未完成部分」仅处理失败候选版本，与「重新生成分享总结」区分，避免一次音频失败就重复调用全部模型。

## 后台交互

- 历史列表和详情增加「重新生成分享总结」主操作。
- 操作说明展示原时间窗口，并说明使用当前配置重新生成三项内容、完成前保留旧版。
- 提交后立即显示候选版本与阶段进度，页面可关闭并重新打开查看，不依赖浏览器保持连接。
- 同一条总结有生成操作进行时，禁用重复提交、单项生成及删除；后端执行相同约束。
- 详情展示本次文字、图片、音频状态和具体错误；失败时提供「重试未完成部分」。
- 保留现有单独生成图片、音频能力，作为已有文字版本的素材操作，收在次级操作中；所有素材必须明确绑定文字版本。
- 版本历史展示创建时间、来源、状态、文字及关联素材；旧文件继续保留。

## 稳定链接与版本隔离

改造前公开报告路径 `/share-summary/reports/{publicToken}` 使用图片记录的 token，页面读取关联 run 的正文，并另外查询该 run 最新成功音频。直接覆盖正文会产生新文字与旧图片、旧音频混用的问题。

建议引入以下关系：

- 分享总结记录作为稳定身份，保存当前公开版本指针及稳定公开 token。
- 每次重新生成创建版本记录，保存文字、窗口、输入及配置快照、阶段状态和失败信息。
- 图片、音频绑定版本；公开版本明确指定所展示的图片、音频记录。
- 已有公开报告 token 兼容解析至所属分享总结，再读取其当前公开版本。旧分享页面地址因此可显示完整新版本。
- 图片、音频文件 URL 保持不可变；新素材使用新 URL，避免已有长期缓存返回旧文件。
- 后台历史版本按版本读取，不使用「该 run 最新成功素材」拼装历史内容。
- 页面一次读取同一公开版本的文字、元信息和素材标识，不能在并发切换时混用两个版本。

存量记录需要补建基础版本及 token 映射。已有素材按现存关联归档，不能声称还原出数据库没有记录过的完整历史输入。已存在缺失素材的页面在升级后仍保持可访问，新整体再生成按三项全部成功规则发布。

链接内容更新后，服务端返回新版本；第三方平台此前缓存的分享卡片不保证即时刷新。

## 服务端改动

- 新增 `POST /api/admin/share-summary/runs/{runId}/regenerate`，异步受理并返回 `202`、候选版本标识和状态。
- 新增版本列表/详情及失败版本重试接口；现有详情响应补充公开版本和活跃候选版本进度。
- 在数据库层保证同一总结最多有一个活跃生成操作；同一请求重复提交应返回已有操作，独立并发请求返回明确冲突。
- 引入独立编排服务，负责文字成功后启动两个素材分支、汇总完成情况并发布，避免分别调用现有三个接口造成部分内容提前可见。
- 生成过程异步运行，进度持久化；启动时或定期回收超时任务，保证服务重启后不会永久显示生成中。
- 发布使用预期版本校验；被超时终止或被新操作替代的旧回调不得发布。旧工作结果仅能更新对应有效尝试。
- 单项素材生成、删除与整体生成共用并发约束。单项更新同样只能选择当前文字版本的素材。
- 整体重新生成不推进定时任务的完成窗口，也不修改原触发方式；版本单独记录重新生成来源。
- 本次涉及的成功通知应在整体发布后触发，避免素材中途成功就发出尚未完整就绪的分享链接；错误通知保留阶段信息。

## 验收重点

1. 对历史日报重新生成，窗口仍为原日期，任务当前日期不会改变它。
2. 文字先成功，图片与音频随后生成，且二者输入来自同一版本。
3. 新版本未全部成功前，原链接返回的文字、图片、音频均属于旧公开版本。
4. 三项成功后，原链接统一显示新版本，旧素材直链和后台历史仍可访问。
5. 任一阶段失败不影响旧公开版本；重试只处理未完成部分。
6. 重复点击、并发请求、服务重启、超时后的迟到回调均不会重复发布或覆盖较新版本。
7. 配置缺失、任务删除、无输入、禁用自动生成等情况符合上述规则。
8. 存量链接兼容、公开页面版本一致性、现有单项生成及定时执行通过回归验证。

## 建议实施顺序

1. 增加版本数据与稳定链接解析，完成存量兼容。
2. 实现异步编排、阶段状态、并发保护、原子发布及失败重试。
3. 接入后台入口、进度和历史展示，调整单项操作的版本绑定。
4. 覆盖验收场景，并同步现状说明与 API 文档。

## 实现说明

- 版本复用 `share_summary_run` 保存正文与素材关联，新增 `share_summary_revision` 保存编排状态及快照；候选版本不进入普通执行记录列表。
- `share_summary_publication` 保存原总结身份、当前公开版本及稳定分享地址。历史图片 token 仍可解析到原总结的最新公开版本。
- `share_summary_regeneration_request` 保存请求幂等标识。客户端可通过 `Idempotency-Key` 重复提交同一次操作。
- 新音频使用 `share_summary_audio_token` 的独立随机 token，地址绑定到具体音频文件；旧图片 token 形式的音频链接继续兼容。音频不必等待图片才能取得可用地址。
- 版本历史接口为 `GET /api/admin/share-summary/runs/{runId}/versions`；重试接口为 `POST /api/admin/share-summary/runs/{runId}/versions/{versionId}/retry`。
- 后台在有生成任务时每 3 秒刷新进度；生成完成后停止轮询。数据未变化时不重建详情中的音频播放器。
- 任务的排队状态、阶段和截止时间持久化。进程中断后，未完成任务到达截止时间会转为失败，支持人工重试；本期不自动重放可能已调用上游的请求。
- 新增数据库表通过现有启动初始化流程幂等创建，存量正文和素材无需复制；旧 run 直接作为初始版本。
- 整体成功通知在发布事务提交并清理数据库连接后创建，再交给异步线程发送。不能在 `afterCommit` 回调内直接插入通知记录，否则发送线程可能读不到尚未提交的记录，留下 `PENDING / 0 次`。重复状态检查不会再次发送，升级不自动补发历史通知。
