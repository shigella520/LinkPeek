# 首轮迭代：正确输出与报告工作台

日期：2026-11-25。分支：`codex/quality-and-report-workspace`。

本轮交付运行实例审视方案的第一批修复和核心前端调整。保持原始分享 URL、Provider SPI、现有风格提示词、报告与资产历史；没有更新线上容器或发送真实通知。

## 已实现

### AI 内容正确性

- Responses 只提取 assistant message 中的 output_text，忽略 reasoning 和工具项；兼容缺失 type/role 但明确标记 output_text 的网关响应。
- 存在结构化 output 数组时不使用顶层重复文本覆盖它；只有顶层 output_text 的兼容响应仍受完成状态检查。
- 拒绝不完整、失败、拒绝、空输出，以及 Chat Completions 的 length/content_filter/tool_calls 终止结果。
- 标题必须为单条非空行，最多 120 个 Unicode code point；拒绝结构化对象和显式推理标签。多行说明或长段落不会被简单截断后计为有效标题，失败沿用已有 Provider fallback。
- 风格缓存键增加 `title-format-version=2`，避免新请求复用旧解析结果。旧资源地址和历史记录保留，原有单条缓存清理入口仍可用。
- 文字 AI 日志移除原始正文；图片/音频请求正文及图片 curl 调试信息降至 DEBUG。上游图片/音频错误诊断与数据库快照仍沿用原机制。

### 分享入口

- 链接构建器提取为可单独测试的 `dashboard/link-builder.mjs`。
- 输入后调用已有轻量支持接口；支持时复制 LinkPeek 链接，不支持时复制原链接。无法验证时明确说明，并只允许复制原链接。
- 输入更新立即禁用旧结果；取消旧请求并使用序号隔离迟到响应，不会把前一条链接的支持结果套到后一条。
- 中文操作文案明确“复制完成”与“卡片生成”的区别；保留全部自定义 Style Key。

### 通知

- 为超过 24 小时且当前进程没有正在执行的 PENDING 记录提供 `pendingExpired` 展示标识。数据库状态不变，不自动清理或补发。
- 过期待处理通知手动重发前明确提醒会向原渠道发送历史消息。
- 临时 DNS 失败保留为可重试 I/O 故障；协议和地址策略拒绝是不可重试错误。测试验证 DNS 最多尝试 3 次，阻止地址仅尝试 1 次。
- 当前进程维护在途投递 ID，避免重复点击排队发送同一记录；最终失败后不额外休眠。
- 投递状态显示“等待发送 / 已送达 / 投递失败 / 过期待处理”，不再把业务失败事件与投递 SUCCESS 混为同一个状态。

### 前端工作台

- 分享总结分成“报告”和“定时任务与配置”，默认进入报告。
- 历史列表从 9 列收敛到 4 列：报告、统计窗口、生成状态、操作。正文、图片、音频分别显示状态。
- 每行常驻“查看 / 分享 / 更多”；重生成、单项生成与删除放入更多，复制入口放入分享。
- 详情优先显示服务端安全渲染的 Markdown，保留原文和版本记录；提示词快照、整体重新生成说明折叠展示。
- 整体重新生成确认包含原统计窗口及“三项完成后统一更新”的说明。
- 详情 URL 保存 report 参数，可刷新恢复；关闭详情返回原列表。报告与任务视图写入 summaryView 参数。
- 列表/通知/日志异步请求用序号避免旧结果覆盖新筛选；刷新任务选项保留当前任务选择。
- 耗时以毫秒、秒、分展示；生成/投递状态中文化。
- 日志“自动刷新”与“跟随最新”分开；向上阅读时暂停自动跳底。
- 窄屏报告列表转为分段卡片，常用操作目标至少 44px。
- 弹层增加焦点返回与 Tab 循环；折叠区域中的隐藏控件不进入循环。
- 报告详情进度更新时仅对同一音频 URL 恢复播放位置、速度和播放状态，不把旧进度应用到新版本音频。

## 发布注意

1. 本轮没有 schema 变更，也不会重写旧任务、报告或通知状态。
2. 风格缓存版本变化会让首次访问走新生成链路；不会主动批量调用模型。第三方聊天平台自己的旧卡片缓存不保证立即刷新。
3. 当前投递在途保护只在单进程内有效，不能宣称重启恢复或 exactly-once。过期标识只是运维提示，不是永久失败判定。
4. 生产部署前记录不可变镜像 digest，按既有流程备份数据库与资产。发布后的观察应区分新增错误、历史记录与第三方故障。
5. 本地测试用实例不应当作生产部署；其中报告和失败状态均为合成验收样本。
