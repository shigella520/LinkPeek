### 2.1 已确认：模型推理文本进入标题

2026-11-25 15:27:57 的一条 LINUX DO 链接记录，显示的是生成标题的过程说明，仍标记“已渲染”。同时间的响应日志包含 `output[].type=reasoning` 和 `content[].type=reasoning_text`。

本地 `OpenAiCompatibleTextClient.extractResponsesText` 遍历所有 `output[].content[].text`，没有限制输出类型；`AiTitleService.cleanTitle` 再取第一条非空行。该实现可以解释现场现象，是高置信根因；修改后需用脱敏、合成的同结构响应回归验证。

改进：仅接受最终 assistant message 的 output_text；顶层兼容 output_text 单独处理；忽略 reasoning、工具调用及拒绝内容；检查响应完成状态、截断与空输出。标题校验失败不得计为成功或写入正常风格缓存。保留现有艺术化风格，不擅自更改用户提示词；格式正确与事实质量分别评测。

异常缓存处理：引入生成结果格式版本进入缓存键，并提供单条重新生成/失效操作。历史异常标题先列出候选，不能升级时无差别清空缓存或重写全部统计标题。聊天客户端此前缓存的卡片不保证立即刷新。

### 2.2 已确认：缓存标记混合了不同请求路径

样本中 preview 的 `cacheHit=true` 有 17 次，P50 10.144 s；`false` 有 20 次，P50 10.316 s。截图最后一组 false/true 分别为 7,707/7,701 ms，缩略图为 3,808/3,790 ms。

本地 `PreviewService` 在等待锁后再次命中缓存也返回 true。因而这些成对完成的请求与“等待首个请求生成后复用结果”相符，不能据此断言磁盘缓存读取需要数秒。样本也出现同一链接后续命中仅 5 ms 的记录。

改进：保留并发去重，新增 HOT_HIT / COALESCED_WAIT / MISS_GENERATED / FALLBACK 路径及 lockWaitMs、fetchMs、aiMs、renderMs、cacheWriteMs、evictMs。前端区分“本次请求路径”与“当前缓存文件是否存在”。

代码还显示每次部分缓存写入/缩略图生成会执行 `evictIfNeeded`，枚举缓存文件；水印 SVG 在渲染时解析。这是待 profiling 的成本点，不是已证实的 3—5 秒根因。先分段计时，再决定低频清理、索引和静态资源复用。

### 2.3 已确认：标题生成存在长尾

15:23:10 的 NGA 创建记录，总耗时 40.644 s，其中 AI 39.268 s。普通跳转 P50 为 1 ms，说明应优先处理爬虫预览生成链路，不能笼统归因于整个站点性能。

改进：标题与总结使用独立模型优先级和总预算；上游超时、降级等待及锁等待均纳入截止时间。预算耗尽使用现有原始元数据降级。设定兼容开关，从基线采样后灰度启用，不承诺第三方聊天客户端会在异步完成后重新抓取。

### 2.4 已确认：存在长期待发送通知

通知筛选得到 3 条 PENDING，均为 2026-06-12，尝试次数 0；截至检查日相差 166 个日历日。另有 9 条 FAILED，最近失败在 10 月 8 日，包含 502 与 DNS 临时解析失败。11 月 23 日最新总结通知为 HTTP 200、1 次、691 ms，不能将历史异常描述为当前整体不可用。

本地队列缺少完整持久化恢复；DNS 校验抛出的 IOException 被包装为 IllegalArgumentException，随后进入不可重试 RuntimeException 分支，与历史 DNS 失败仅 1 次的现象相符。缺少当时进程日志，不能确定 6 月记录最初卡住的原因。

改进：区分永久地址拒绝与暂时 DNS/网络错误；保存每次投递尝试，记录总耗时、下一次重试时间和租约。新任务从数据库领取，支持重启恢复与有界重试。历史 3 条先标识为过期待处理并提供审阅入口；禁止上线时自动补发数月前通知。

## 3. 前端交互审视

### 3.1 首页：输入成功不等于平台支持

实测填入 `https://example.com/article` 后，页面显示 Ready to copy，并生成 LinkPeek URL。当前 JS 只校验 http/https，未调用仓库已存在的 `/api/preview/support`。

目标流程：粘贴链接 → 支持判定 → 选择有说明的风格 → 复制分享链接。不支持的平台提供“复制原链接”；判定失败明确显示“暂时无法验证”，不能当作已支持。避免自动触发付费 AI 生成。

提供中文风格名称、短说明与示例；保留现有 key 和 FREESTYLE 行为。文案区分“链接已复制”和“卡片已生成”，不让用户误以为复制动作完成了爬虫渲染。

### 3.2 分享总结：阅读与分享应优先于重新生成

现场每行同时显示 8 个操作：整体重新生成、详情、重新生成图片、重新生成音频、复制 OG、复制图片、复制音频、删除。整体重新生成是深色主按钮；列表有 9 列，行高被操作区撑大。桌面首屏也只能看到很少的历史记录。

建议将同一页面分为“报告”和“定时任务”两个视图；图片/TTS 配置放进配置入口。报告列表显示：标题/周期、整体状态、文字/图片/音频/通知阶段、更新时间；常驻操作仅“查看”“分享”“更多”。

详情优先展示渲染后的报告、图片和播放器；技术信息、输入快照、版本历史、重试日志按需展开。保留原始 Markdown 查看/复制入口。现有模块 hash 导航和上次模块记忆已经存在，应扩展到记录详情和过滤条件，而非重复建设。

整体重新生成收进更多操作，执行前清楚显示原时间窗口、将生成的三项内容和保持旧版可访问的规则。失败时优先“重试失败部分”；删除使用独立危险区。所有按钮在请求期间有一致的忙碌状态和重复点击保护。

### 3.3 状态要说清楚“谁成功了”

当前 UI 混用 SUCCESS / PENDING / NOT_GENERATED / SCHEDULED / to 与中文。通知记录的“数据爬取请求失败 + SUCCESS”容易被误读。报告正文成功也不等于图片、音频和通知全部完成。

建议：状态显示“已发布、生成中、部分失败、无可总结内容”等中文；详情展示内部状态码。通知分别显示“事件：抓取失败”和“投递：已送达”，避免一个 SUCCESS 概括全流程。耗时统一显示 6.7 秒、4 分 41 秒，精确毫秒放详情。

成功报告的阶段状态从实际资源和投递记录推导；缺失或旧数据不可伪造“已发布”。旧报告链接和历史兼容必须保留。

### 3.4 日志页：从终端文本转向可排查事件

当前日志窗行很长，默认请求/响应正文占主要空间；最新片段中 151 行已约 197 KB。代码每次刷新强制滚到底；逐行按级别过滤也可能丢失多行异常堆栈。

建议默认事件列表：时间、级别、模块、事件、耗时、结果；点击展开完整上下文和脱敏正文。支持关联 previewKey / runId / deliveryId、时间范围及轮转日志。保留原文模式；“跟随最新”独立开关，用户向上阅读时暂停跟随，刷新不夺走滚动位置。空日志、无匹配、读取失败明确区分。

### 3.5 Dashboard：指标定义与使用目标

当时页面显示独立链接 252、新增链接 253；AI 成功率 100%，但已有异常标题。不能据此直接判断统计数据损坏：SQL 中独立链接来自创建/打开事件的 previewKey 去重，新增来自 stats_link.first_seen_at，两者口径不同。

建议给指标注明时间窗口、去重单位、事件范围；同时区分“模型请求成功”和“标题通过校验”。用固定样本检验原始链接/风格链接如何去重。上半屏以生成分享链接为主，统计摘要精简，详细分析保留在统计区。避免在同一屏重复展示相同计数。

### 3.6 适配与可访问性验收

移动端本次未验证，实施时必须覆盖 390px、768px、桌面 1440px：列表改为摘要卡或可展开行；常用操作不依赖横向滚动；触控目标不小于 44px；错误和保存结果能被读屏识别。弹层支持 Escape、焦点限制与关闭后焦点返回；长任务刷新不重置播放器。

## 5. 验证与上线

1. 先记录镜像 digest、源码 commit、数据库 schema 版本。`:dev` 标签可变，回滚必须能定位不可变镜像。
2. 对 SQLite 使用一致性备份并连同资产目录验证恢复；WAL 模式不能简单只复制主 db 文件。
3. A1/A2 在脱敏合成响应和数据库副本上验证；以类型信息复现异常，不把原始推理正文写入测试仓库。
4. 浏览器验收链：复制支持链接、不支持时复制原链接、查看报告、分享、重生成确认、部分失败重试、通知详情、日志关联、刷新恢复播放器。
5. 所有故障注入、通知补偿和生成测试在隔离测试实例及本地假接收端执行，避免真实外发及模型费用。
6. A/B/C 分开提交和发布，保留兼容开关。业务验收通过后再更新运行实例。
7. 发布后观察同口径 24—72 小时：异常标题数、降级率、各路径耗时、过期待发送数量、任务失败原因。不把短窗口小样本的 P95 当作稳定 SLO。

建议初始性能验收：固定测试环境下热缓存预览不访问外部 AI/抓取服务，同键并发只生成一次；以配置总截止时间约束冷生成，并验证后续结果不会覆盖更新版本。生产 P95 目标在取得分段基线后确定。

## 6. 实施边界

- 本轮保持 Java 17 / Spring Boot / SQLite / 原生前端；先按业务模块拆分文件，不引入整套新前端框架或消息中间件。
- 保留用户已配置风格。此次确认的是响应类型解析错误，不把有意的艺术化表达直接视为模型失效。
- 不自动清理历史通知、不自动重发、不批量重新生成、不改变部署密码。
- 截图含管理凭据，后续共享截图应遮挡；渠道 URL 在列表和日志中隐藏敏感查询参数。交付文档和草图不包含这些值。
- 原始线上日志未复制到仓库；本文仅保存脱敏聚合数据与必要事件时间。
